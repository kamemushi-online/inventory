## Decisions and design notes

### Goal of Phase 2.5

- Speed up the loop of opening real logs repeatedly, checking the schema, selecting channels, load/add, and inspecting waveforms.
- Raise the cadence of field verification before adding more analysis features.
- Current pain points:
  - Parquet path is typed by hand.
  - Channel selection and load operations are physically separated.
  - The loaded / loading / unloaded state is hard to read from a list.

### Handling of plot-side features

- Formal `.pyc.json` compatibility and the proper plot-config spec are left to Phase 4.
- For Phase 2.5, this is treated as a lightweight Rust-internal `session preset`.
- Saved fields are limited to the minimum set useful for field verification:
  - parquet path
  - row layout
  - channel path
  - Line / Step
  - visible
  - color override
  - line width
  - Y Auto / Manual range
  - X range

### Priority of multi-channel selection

- A "check multiple channels in the list, then `Load checked`" UI is being deprioritized for now.
- Reasoning:
  - In field verification, reaching the target channel quickly likely matters more than batch-selecting.
  - Bulk loading requires sorting out avoidance of duplicate time-column reads, partial-failure display, and duplicate handling within the same Row.
  - For 100-channel scenarios, search, state filter, sort, and selected detail are lower-risk and have a larger payoff.

### Handling of channel-list extensions

- `Pinned / Recent Channels` look low-value at this point, so they're on hold.
- Prefix search / prefix grouping seem useful, but operating with the current substring filter / state filter / sort is fine to start.
- If channel discovery hits a wall on real data, a `Prefix` filter mode would be the first low-risk addition to consider.

### On wheel-handling separation

- As row count grows, assigning the normal wheel to vertical scroll is more natural than to X zoom.
- X zoom is now an explicit action, limited to `Ctrl/Cmd + wheel` and pinch.
- Unlike box zoom, this didn't require a new selection state or a rectangle overlay, so the implementation stayed low-risk.

### Box-zoom direction

- For box zoom, the main issue is interaction conflict with the existing `left-drag = X pan`.
- A low-risk option is `Shift + left-drag = X-only box zoom`.
- Preserve normal left-drag pan, horizontal-scroll pan, `Ctrl/Cmd + wheel` X zoom, and double-click reset.
- Box zoom updates only the X range and syncs across all rows.
- Y-axis zoom is kept out of box zoom and handled via per-row `Y Auto / Manual min/max` numeric settings.
- Putting the Y axis into box zoom would bring per-row scope, Auto/Manual switching, and reset behavior into scope, which would slip outside the low-risk improvements that Phase 2.5 aims for.
