## Decisions & Design Notes

- Kept plot-config file handling out of `main.rs`; isolated it in `plot_config.rs`
  - Tolerant parsing at the JSON boundary, the report, and save-JSON generation have different responsibilities from UI and render state
- At the boundary, take `serde_json::Value` rather than deserialize directly into serde types
  - Phase 3's requirement is "partially restore whatever keys we can read," so we want to avoid bringing down the whole file because of a type mismatch on a known key
- Kept `version: 1` compatibility fields and stored Rust-specific information under a `rust` namespace
  - Preserves a top-level shape that the Dash version can read, without losing Rust-side `visible` or per-row style
- `x_range`, selected channel, large preview, cache / LOD / analysis state are *not* saved into the canonical plot config
  - Phase 3 plot config is scoped to Raw channel display structure and display style only
- Plot-config load validates JSON / data_path / schema / apply plan all before commit
  - So we don't break the current `DatasetState` / `ViewState` on failure
- Channel load following plot-config load uses a dedicated path that does not add rows
  - The row layout is already restored from the plan, so reusing `load_selected_channel()` as-is would mix responsibilities
- Kept the default behavior of `scroll_zoom = false`
  - Don't break the Phase 2.5 input separation of "plain vertical wheel does not trigger X zoom"

## Addendum: Apply-to-Current-Data Mode for Plot Config

- Added `PlotConfigApplyMode` to plot-config load
  - `LoadConfigDataPath`: existing behavior. Open the `data_path` from the plot config and swap out schema / dataset / view
  - `ApplyToCurrentData`: apply only the view portion of the plot config against the currently open Parquet schema
- Added an `Apply to Current Data` button to the `Plot config` section of the UI
  - Disabled if no schema is loaded
  - Also disabled while a load job is active, same rule as the existing Load / Save
- Decided the commit policy for `ApplyToCurrentData`
  - Preserve `dataset.parquet_path` / `dataset.schema` / `dataset.shared_time`
  - Preserve the raw channel cache
  - The draw cache must be regenerated, so discard it via `clear_draw_caches()`
  - Preserve `x_range` as the display position on the currently open data
  - Clear `hover_x` since it may depend on the old row layout
  - Apply from the config: row / channel / visible / Line-Step / style / Y range / theme / scroll zoom
- If `data_path` in the plot config differs from the current data, don't make it an error
  - Record it in `ignored_fields` as `data_path=... (using current data ...)` so it surfaces in the warning summary
- Added regression tests for current-data apply mode
  - The current dataset and raw cache are preserved
  - Only the draw cache is cleared
  - `x_range` is preserved
  - Hidden channels are not auto-loaded
  - A `data_path` mismatch remains in warnings
