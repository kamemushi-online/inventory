### Bug fixes (a618453 — fixed on proto_3_1 before the integration)

**Bug 1: Row 1 disappears after loading a plot config**
- Cause: when `load_plotconfig` updated `rows-container`, the pattern-matching Input in `manage_rows` (the `row-delete` button) changed, which spuriously fired the callback. `ctx.triggered_id` came in as `{"type": "row-delete", "index": 0}` and Row 1 got deleted.
- Fix: in `manage_rows`, only process the event if the delete button was actually clicked (verified by `n_clicks` being present)

**Bug 2: Width value resets after hitting "Update" following a width change**
- Cause: inside `update_waveform_rows`, the call to `make_ch_settings(used_chs)` wasn't being passed `ch_styles`, so the UI was rebuilt with default values (width 1) on every update
- Fix: changed it to `make_ch_settings(used_chs, ch_styles)`

### External review fixes (d075c5c)

1. **Mismatched return count in `update_waveform_rows()`** — three Outputs declared, but the empty-row branch was returning only 2 elements → fixed by adding `no_update` to make it 3
2. **Insufficient exception handling in `load_plotconfig()`** — added empty-path check, `is_file()` + extension check, and wrapped `read_parquet` in `try/except`
3. **`ts` calculation throws `IndexError` on a single-point dataset** — extracted into the helper `_make_load_status()` with fallbacks for `len(df) < 2` and `ts == 0`

## Decisions / design notes

- Bugs were clustered around the load → render → style-change flow. Pattern-matching callbacks in Dash can fire as a side effect when dynamic components change, so be careful here
- Data init logic in `load_file()` and `load_plotconfig()` overlaps significantly. Hard to fully unify because Inputs/Outputs differ, but extracting helpers like `_make_load_status()` covers part of it
- External review is static-only, but it caught things like return-count mismatches that are easy to miss until runtime. Useful
