# 2026-05-14 Dev Journal

## Today's Theme

Implement range statistics driven by Cursor A/B in the Rust viewer (`code/rust_phase1/`), and tune the statistics-info UI into a practical layout.

## What I Did Today

- Implemented Cursor A/B range statistics
  - Target: channels that are visible and already loaded
  - Even if the same channel appears in multiple rows, it is treated once (no duplicates)
  - Compute against raw data, not the display LOD
  - Statistics: `A`, `B`, `Delta`, `Mean`, `Max`, `Min`, `P-P`, `RMS`, `Slope/s`
- Added a computation cache for the range statistics
  - Skip recomputation when Cursor A/B, the time array, and the target channel set are unchanged
  - Invalidate the cache on cursor repositioning or clearing
- Reworked the Cursor info UI
  - Left side panel keeps only the controls / summary: Cursor mode, Clear, A/B times, dt, etc.
  - Cursor values and the range-statistics table moved to a bottom panel inside the central plot region
  - The bottom panel spans from the right edge of the left side to the right edge of the plot area
  - Added `Collapse` / `Expand` and `Hide`
  - After Hide, the panel can be brought back via `Show cursor info panel` on the left side
- Improved the horizontal-scroll behavior of the statistics table
  - Pinned the channel column, and made only the numeric columns scroll horizontally
  - Lets you read across `A, B, Delta, Mean, Max, Min, P-P, RMS, Slope/s` without losing the channel name
- Warning cleanup
  - `cursor_interval` was raising an unused warning in normal builds, so I marked it test-only with `#[cfg(test)]`
- Added regression tests
  - Range statistics are computed from raw data
  - Visible / loaded / dedup conditions on the target set are respected
  - Statistics cache is reused under identical conditions
- Verification
  - `cargo fmt`
  - `cargo check`
  - `cargo test`
  - Result: `79 passed`

## Decisions / Design Notes

- Took the existing Cursor A/B as the input to range statistics
  - Matches the Phase 4 plan of centering analysis input on Cursor A/B
  - Lets statistics — and future FFT — share the same range spec
- Limited targets to `visible loaded channels`
  - Hidden channels are excluded because the user isn't looking at them right now
  - Unloaded channels are excluded because there's no raw data to compute over
  - Even when the same channel appears in multiple rows, the stats result is a single row
- A / B values use the nearest sample to the cursor time
  - Same idea as the Dash reference
  - Range statistics aggregate over the inclusive range between the nearest-sample points of A and B
- Slope/s is `(B - A) / (cursor_b - cursor_a)`
  - Preserves the sign of B-A even when the cursors are placed in reverse order
- Placed the bottom panel as `Panel::bottom` inside the `CentralPanel`
  - Keeps the left side vertical and only splits the central region top/bottom
  - Matches the requested "from the right edge of the left side panel to the right edge of the plot area"
- Split the statistics table into a channel column and numeric columns
  - A naive horizontally-scrolling table loses the channel name during scroll
  - Pinning the channel column and scrolling only the numbers reads better during real measurement work
- Gave the Cursor info panel both Hide and Collapse
  - Collapse: temporarily expand the waveform area
  - Hide: return to display work that doesn't need analysis info

## Stuck Points and Resolutions

- Putting the statistics table in the left side didn't have enough width — channel names disappeared during horizontal scroll
  - Moved the statistics info to the bottom panel and switched to a pinned-channel-column table
- `cursor_interval` is used in tests but not in normal builds, which produced a `dead_code` warning
  - Added `#[cfg(test)]` so it's excluded from normal builds
- Didn't want the egui bottom panel range to include the left side
  - Reserved the left side first with `Panel::left`, then created the bottom panel inside `CentralPanel`
