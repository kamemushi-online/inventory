# Technology Selection Memo #1

## Background

The current prototype (TypeScript + Vite + Plotly.js) was adopted for the purpose of learning TypeScript.
Now reconsidering the tech stack with FFT analysis, contour plots, and support for long-duration data in mind.

---

## Pain points with the current stack

| Concern | Limits of TypeScript + Plotly.js |
|---------|----------------------------------|
| FFT | Browser-side JS FFT libraries are limited (poor window-function and THD support) |
| Large data | Bound by the browser's memory ceiling (effectively 1–2 GB) |
| Numerical precision | Floating-point precision can fall short of SciPy in some cases |
| Render speed | Drawing stalls once point counts exceed the hundreds of thousands |

---

## Comparison of main candidates

### A. Python + Dash (recommended candidate)

```
Python (acting like FastAPI/Flask) + Plotly Dash (Web UI)
Data processing: NumPy / SciPy / Pandas
```

| Aspect | Rating |
|--------|--------|
| FFT quality | Excellent — SciPy.fft provides window functions, THD, and order analysis |
| Large data | Excellent — NumPy arrays handle GB-class data |
| Render speed | Good — same API as Plotly, with WebGL support |
| Contour plots | Excellent — `go.Contour` / `go.Heatmap` are supported natively |
| Development cost | Good — Plotly.js knowledge transfers (similar API surface) |
| Sharing/distribution | Fair — requires a Python server |

**Strengths for motor-control use**: SciPy includes all the analyses commonly used in control systems, like `signal.spectrogram` and `signal.periodogram`.

---

### B. Python + Panel + HoloViews

```
Panel (a framework that integrates Bokeh/Plotly/Matplotlib into one UI)
HoloViews: efficient rendering of large data (datashader integration)
```

| Aspect | Rating |
|--------|--------|
| FFT quality | Excellent — SciPy available (same as Dash) |
| Large data | Outstanding — **Datashader renders even billion-point datasets quickly** |
| Render speed | Excellent — pixel-bucketed rendering (unbeatable for long-duration data) |
| Contour plots | Excellent — both Matplotlib and Plotly are accessible via HoloViews |
| Development cost | Fair — steeper learning curve than Dash |
| Sharing/distribution | Fair — requires a server (same as Dash) |

**Notes**: For long waveforms (millions of points and up), Datashader "aggregates per pixel and then draws," so the browser does not choke. It is the strongest choice for handling long-duration logs in power-electronics measurement.

---

### C. Python + Streamlit

| Aspect | Rating |
|--------|--------|
| FFT quality | Excellent — SciPy available |
| Large data | Good — depends on memory, but processing is fine |
| Render speed | Good — integrates Plotly/Altair/Matplotlib |
| Development cost | Outstanding — fastest to build (write only Python) |
| Sharing/distribution | Fair — requires a server, but free hosting on Streamlit Cloud is also possible |

**Weakness**: Limited freedom for interactive UI (fine-grained control like linked cursors is hard to implement).

---

### D. Tauri + Python subprocess (desktop app)

```
Tauri (Rust shell) + Web UI (TypeScript/React)
Heavy work is offloaded to Python via subprocess
```

| Aspect | Rating |
|--------|--------|
| FFT quality | Excellent — can call into Python/SciPy |
| Large data | Excellent — runs locally, so memory constraints are loose |
| Render speed | Excellent — native app with GPU support |
| Development cost | Poor — must manage Rust + TypeScript + Python in parallel |

Over-engineered for the current stage. Parked as a future option.

---

## Selection criteria summary

| Criterion | Importance | Recommended direction |
|-----------|------------|------------------------|
| FFT, window functions, THD | High | Python is required (SciPy) |
| Long-duration data (millions of points and up) | High | Panel + Datashader is the strongest |
| Contour plots (operating-point maps) | High | Easiest to compute on the Python side and render with Plotly |
| Interactive UI (zoom, cursor) | Medium | Dash or Panel both work |
| Development speed (solo developer) | Medium | Streamlit > Dash > Panel |
| Use without a browser | Low | Tauri or PyQt direction |

---

## Conclusion / recommendation

- **For handling long-duration data seriously** → Panel + HoloViews + Datashader
- **For getting something working quickly first** → Python + Dash

If TypeScript was chosen "for learning," the Python stack is a much better fit for the intended practical use (power-electronics waveform analysis). With SciPy and NumPy at hand, FFT and contour plotting work "just by writing the code."

**Phased migration plan**: Build Phase 1 in Dash, then migrate to Panel + Datashader when large data starts to choke.
