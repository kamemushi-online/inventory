# Technology Selection Memo #2 — Dash Deep Dive (Second Opinion)

## Conclusion

Dash is **"a framework for building full-featured, React-style analytical web apps using only Python."**

---

## 1. What is Dash?

Dash is an open-source framework for building data-visualization apps, developed by **Plotly** (the company famous for the graphing library).

- **Pure Python:** You can build a serious UI in Python alone, without needing HTML, CSS, or JavaScript (React) knowledge.
- **Flask + React + Plotly.js:** Internally it uses **Flask** on the server side and **React** plus **Plotly.js** on the client side. Dash wires them together behind the scenes, so developers can focus on data work.

---

## 2. Advantages for motor-control and power-electronics analysis

### Strong integration with SciPy (FFT and analysis)

The analytical capabilities that were weak in TypeScript (JS) can be invoked directly on the server side as **SciPy** when using Dash.

- High-precision FFT with window functions (Hann, Hamming, etc.) applied
- Computing THD (total harmonic distortion) and order analysis
- Time–frequency analysis using `signal.spectrogram`

### Reusing the Plotly.js skill set

Since the current prototype already uses Plotly.js, the chart configuration knowledge (the `layout` and `data` dictionary format) carries over directly to the Python side.

### Flexible UI (callback system)

Dash's defining feature is **callbacks**.

- "Move a slider" → "recompute the FFT on the Python side" → "the chart updates instantly"
- This interactive behavior can be expressed as plain Python functions.

## 3. Structure of a Dash app

A Dash app consists of two main pieces.

1. **Layout:** what the app looks like (placement of buttons, charts, dropdowns)
2. **Callbacks:** what the app does (which charts update, and how, when inputs change)

## 6. Handling heavy data: data format selection (addendum)

In long-duration, high-speed logging for motor control and power electronics, CSV files bloat in size and can take minutes just for I/O. The following binary formats are under consideration.

### Comparison of recommended data formats

| Format | Compression | Read speed | Notes |
|--------|-------------|-----------|-------|
| **CSV** | Low (none) | Slow | Text and easy to inspect, but heavy |
| **Parquet** | **Very high** | **Fast** | The current de facto standard for analytics |
| **HDF5** | High | Medium–High | Strong affinity with MATLAB `.mat`; good for hierarchical data |
| **Feather** | Medium | **Fastest** | Minimal read/write overhead; ideal for temporary caches |

### Per-format details

**A. Apache Parquet (recommended; decided)**
- Compression: typically reduces size to 1/5–1/10 of CSV
- Columnar format: can extract specific channels (e.g., only the voltage) without scanning the whole file
- Loads at top speed with `pandas.read_parquet()`

**B. HDF5 (`.h5`)**
- MATLAB's `.mat` (v7.3 and later) is actually HDF5 underneath
- Supports hierarchical (folder-like) structure inside a file → multiple experiments plus metadata can live in one file
- Even huge files can be partially loaded by index range

**C. Feather**
- Optimized for read/write speed rather than compression
- Ideal for local temporary caches

## 7. Data format conversion: MATLAB (.mat) → Parquet

**Policy**: Panel_y treats **Parquet as the standard format**. MATLAB data is converted as preprocessing.

### Conversion code example

```python
import pandas as pd
import scipy.io

# Older format (v7.2 and earlier): use scipy.io.loadmat
mat_data = scipy.io.loadmat('motor_log.mat')
df = pd.DataFrame({
    'time':    mat_data['time_vector'].flatten(),
    'current': mat_data['iq_data'].flatten()
})
df.to_parquet('motor_log.parquet', compression='snappy')

# Newer format (v7.3 and later): use h5py or pandas.read_hdf
# df = pd.read_hdf('motor_log.mat', key='dataset_name')
# df.to_parquet('motor_log.parquet', compression='snappy')
```

### Pros and cons of conversion

| Comparison | HDF5 (.mat) | Parquet |
|------------|-------------|---------|
| **Strengths** | Complex hierarchical structures, holding matrix data | **Fast column-wise extraction, high compression ratio** |
| **Python affinity** | Read/write through libraries | **Best affinity with Pandas (de facto standard)** |
| **Loading in Dash/Panel** | Can be slow in some cases | **Dramatically fast** |

### Implementation notes

- **Preserving dtypes**: Parquet keeps the schema (type information) strictly → values can be stored while keeping precision like `float32`
- **Handling metadata**: Sampling rate, experiment conditions, and other metadata are typically managed in Parquet's custom-metadata area, or in a paired sidecar file (e.g., JSON)

## 8. Rendering strategies for large data

Sending millions of points straight to the browser through Dash will freeze Plotly. Mitigations include:

| Technique | Summary |
|-----------|---------|
| **LTTB (Largest-Triangle-Three-Buckets)** | Algorithm that reduces point count while preserving the waveform's features (peaks) |
| **Datashader** | Python aggregates data by "pixel density" and sends an image to the browser. Combined with Panel, it is the strongest option |
| **Downsampling (decimation)** | Control the number of transmitted points based on zoom level (implemented inside a Dash callback) |
